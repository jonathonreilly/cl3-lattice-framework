## A genuinely different future memory architecture

If pursued in a separately frozen campaign, use one minimal stdlib supervisor plus one worker, eliminating the resident bootstrap layer by exec-replacing it with the verified worker process (or executing the supervisor in the outer process). Preserve independent outer enforcement, but make the actual number of resident interpreters part of the design. Stream every hash in bounded chunks. Create a memory ledger for maximum simultaneously live real buffers and explicitly release/reload representatives from verified disk files before the second-source and final-assembly phases.

A worker redesign should own a fixed workspace rather than rely on allocation/free behavior: preallocated CG x/r/p/ap, reused action scratch buffers, in-place updates only where arithmetic order is retained or recertified, and streaming output/hash. Each altered arithmetic path requires same-kernel tiny CAR and fresh residual controls; reusing the old time benchmark is insufficient. Avoid adding21 full permutation tables. Preserve exact norms and all certificate obligations.

The cheapest informative NEW cost contract would use the complete final supervisor/worker topology, source checks, and a synthetic allocation schedule that commits/touches the worst declared buffers, plus one fixed non-solving action if separately authorized. It must cover retained-representative/source phases and checkpoint I/O, report per-PID/time/stage RSS and exact buffer ledger, and include all loader baselines.
