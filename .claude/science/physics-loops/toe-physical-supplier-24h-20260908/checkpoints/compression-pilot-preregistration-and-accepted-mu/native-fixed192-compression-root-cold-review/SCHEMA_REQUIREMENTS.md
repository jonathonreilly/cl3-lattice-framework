# Prospective external schema review: worker contract

Read worker.py, pivot_resume.py, reader.py, run.py, CONTRACT and PROTOCOL. This is a preparatory source review, not acceptance of a not-yet-supplied external monitor. No native input loader, index, entries, pivots or saved result has run here.

The executable maximum is FOUR paired pivots PER orbit, not an unconditional four: PASS_BOTH, RESIDUAL_PASS_COORDINATE_FAIL and PRECISION_STALL may return early. PAIR_CAP must have4. Five orbits must be exactly IDs0..4 in the fixed ordered list. Both complete status strings distinguish completed probe from scientific target attainment. All-scientific-targets-met must equal all five statuses PASS_BOTH; completion alone never implies small residual.

Required root checks:

1. Bind runtime, contract, authorization/binding and RESULT digest to WORKER_COMPLETE; require exact integer IDs/pairs (exclude bool), finite positive worker/result timings, positive integer RSS and fixed caps. Return0 and absence of FAILURE/DISPATCH_FAILURE/IMMUTABILITY_FAILURE are necessary. Keep root external elapsed/tree receipt independently.
2. Require result status COMPLETE_FIXED_FOUR_PAIR_PROBE, worker status COMPLETE_COST_PRECISION_PROBE_ONLY; five unique ordered IDs0..4, allowed status set, pairs0..4. Bind every ORBIT_i/RESULT and EVENTS digest to its outer row. Inner status/pairs must match. Status PAIR_CAP implies4, early status not necessarily4.
3. Inner history length equals pairs; selected indices unique in0..398, chirality matches canonical labels, positive integer192 interval pivots, complete g/j rows each399 valid endpoint pairs. HISTORY.json exists and agrees with inner history whenever pairs>0; zero pairs legitimately creates no HISTORY file. Each persisted pivot_saved precedes the next checkpoint. HISTORY context must equal CONTEXT (binding/source/radii), orbit correct. Hashes for EVENTS bind all retained history even though outer rows do not separately hash HISTORY.
4. Locate the final checkpoint in EVENTS. It includes pairs, rational raw_residual_upper, coordinate_radius_squared and both booleans. Recompute exact threshold comparisons: raw<=1/(1062*10^6), d²<=1/40000². PASS_BOTH requires both, RESIDUAL_PASS_COORDINATE_FAIL requires first only, PAIR_CAP/PRECISION_STALL require residual false. Final result's optional coordinate_radius_squared must match checkpoint for residual-pass returns. Do not infer coordinate pass from lack of a reported value in PAIR_CAP.
5. The coordinate intervals are per pair,2 rows,399 entries, each integer midpoint and nonnegative integer radius. Recompute d²=sum_j weight_j radius²/2^384, weights2 for396 pole halves and1 for3 appended columns, summed across both rows and all pairs. Final diagonals_complete has399 intervals; raw residual upper is sum weighted upper endpoints/2^192. Structural labels are source-bound; root need not redo native entry arithmetic.
6. PARTIAL on clean completion is the last orbit4 checkpoint (worker does not write a new terminal PARTIAL). Its content must equal the last event. On failure, current before every diagonal or pivot_entry is retained; completed row/diagonals precede dependent gates. Index stage has mode but not per-file byte position, an honest granularity limit. Worker failure preserves completed orbit rows, and final descriptor immutability failure has its own file.

No need for a runtime status mutation: dispatcher changes only in-memory binding status after exact root authorization. Worker never passes resume, so no continuation is executed. Future authenticated continuation is a different contract.

Potential pitfall for monitor implementation: requiring HISTORY for an early zero-pair stall would reject legitimate completed cost evidence. Conversely accepting only RESULT/WORKER_COMPLETE without EVENTS checkpoint reconciliation would not verify the claimed scientific gates. These requirements certify retained schema/accounting, not correctness of native compression arithmetic; its source proof and reader reviews remain load-bearing.
