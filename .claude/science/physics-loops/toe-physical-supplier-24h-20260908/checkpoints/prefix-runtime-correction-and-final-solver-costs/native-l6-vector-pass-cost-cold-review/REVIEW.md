# Fixed vector-pass cost body review

Arithmetic/format design PASS, prelaunch retention and final binding corrections requested. This is source review only; no 2^20 array, operator, solve, norm scan or micro execution. The reviewer previously authored the general error-envelope design; this cost body is primary-authored. Complete sources listed in READ_HASHES were read; the broader integration is not approved by this review.

Each of sixteen groups performs two length-2^20 dot products, three scalar/vector multiplies and three add/subtract vector operations. The updates use new r in p=r+p/4, and the fixed coefficients 1/8,1/16,1/4. Three full-vector finite checks and one scalar finite check are inside its timer. Thus timing includes those checks but excludes writing PARTIAL. These are representative dot/AXPY-shaped costs, not actual CG steps or convergence evidence; the two dot products are self-products, whereas future p·Ap need not be. No claim that NumPy dot has the certified ufunc rounding envelope follows from this cost fixture.

Initial arrays are deterministic exactly representable dyadics. Sixteen groups cannot overflow or approach underflow at these scales. The real NPY schema and raw interleaved little-endian export preserve each binary64 bit, including signed zero. Verification compares integer bit patterns and requires the unused lane to be positive zero. The fixed real phase is valid. The general verify function does not validate an arbitrary phase argument, but the micro calls its real default; broader callers should not infer phase-domain validation from this check.

The norm adapter visits all entries, accumulates exact 2^-2148 squares in full occupation buckets, and obtains a rational upper square root by integer arithmetic. Its binary64 integer decoding is correct. The upper bound is not an exact square root; the exact square/buckets are the useful independent bridge to the raw-complex scanner. In the present body those buckets and the export receipt are discarded, preventing the promised hash/bucket postcomparison without separate rescans.

Requested minimal changes: retain NPY hash and export receipt; retain integer norm buckets/total; persist conversion timing before beginning the scan; maintain current stage and partial timings on exceptions. The final output directory being fresh is good, but the external process-tree watchdog and failure receipts remain required. Proposal says arrays/hashes are retained, whereas only final x is saved; either name that retained final vector explicitly or retain the other promised vectors. Runtime/source binding must include the actual micro, formats, proposal and all imported modules in a dedicated frozen contract; IMPLEMENTATION_CHECKPOINT currently omits micro/formats. Root's external dispatcher is not yet present, so no full runtime/CLI readiness verdict is possible.

The same-process FP guard checks rounding mode and selected ufunc bit patterns before/after, honestly not a universal proof. A 30-second/384-MiB external contract must include imports, allocation, all I/O, norm/export, guard checks and cleanup. Preserve all elapsed overhead rather than scaling only the sixteen timed groups. No physical execution should begin from this review alone.
