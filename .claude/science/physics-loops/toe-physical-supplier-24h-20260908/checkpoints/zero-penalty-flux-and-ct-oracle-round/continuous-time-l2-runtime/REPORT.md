# L2 CT runtime construction

This runtime supplies a prospective initializer and physical measurements, without a stochastic launch. It consumes reviewed exact oracle8b5661b7 and conditional a18312e. All preserved conditional/bridge/geometry bytes match those sources except the explicit Tape delta: consume a supplied iterator lazily, retain exhaustion failure, and fail the whole block at4096 variates. The kernel algebra, inverse-event recursion, and final quotient/integrity checks are unchanged. Per-block new-event cap4096 and inverse bracket tolerance1e-12 are numerical limits, not certified distribution accuracy.

The integer initializer uses the saved exact count weights and backward columns. It samples count, initial state and each diagonal/labeled transition by integer cumulative weights. The chosen label path and sorted times are independent as prescribed. Actual count-zero and count-two/nonself-plus-self paths are exercised with supplied tapes. Variates.randbelow uses rejection from ideal uniform bits; its4096-trial failure ends the whole job. Finite53-bit time uniforms may include zero: boundary or collision aborts initialization without redraw. No claim of continuous-target TV for machine times is made. The explicit ideal count truncation bound remains separate.

Runtime.block uses the original full-scan conditional, then replaces the accumulated initial-state proof tape by its canonical BFS witness. The physical initial configuration, all event times/labels and all observables remain identical. This avoids artificial witness growth without changing the path law. It does not implement local-event indexing, improve spatial mixing or establish a cost bound.

Measurements cover the exact12 prospective raw observables. The path is right-continuous at its events; a machine event precisely at the midpoint is assigned to the post-event state. Time-integrated flippability uses every physical interval. Endpoints supply symmetric h, hLhR and Xh; four changed links per event give count/(6T). Hexadecimal floating-time serialization round-trips bit-for-bit. Full validation and seed-component witness checks run at construction, draw and load.

Deterministic checks cover all864 BFS states, literal count/path choices and rejected bit candidates, collision/budget failures, four constant/one-event paths and96 fixed-tape blocks compared byte-for-byte in scientific payload with the original conditional. These fixed tapes are algorithm controls, not Monte Carlo data or evidence of calibration. ROOT-created RESULT.json reports the actual count/resources. Source hashes are frozen separately. A future profile must first freeze complete end-to-end coverage, total startup/outer overhead and failure rules; a scientific calibration needs its own prospective plan.
