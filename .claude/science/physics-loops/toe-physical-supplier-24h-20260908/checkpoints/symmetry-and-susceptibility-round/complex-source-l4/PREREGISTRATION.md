# Staged L4 tilted-source comparison — proposal only

No implementation extension or production is launched here. Root requested a matched reference and then required an RK complex-source validation gate. The previously reviewed L2 kernel stores REAL six-mode O; directly reusing it for L4 harmonic1 is wrong. This proposal explicitly requires a new independently reviewed complex-cache implementation before either stage.

## Target and required code change

Same periodic L4 component from n_a(r)=r_a mod2,192 binary links and192 geometric faces. For each harmonic h=1,2 define X_h=sum six |O_ab(2pi h/4)|², using all six transverse channels. Track complex O with signed complex delta; compute abs², never real-part square or O². One source at a time: H_lambda=VNf-A+lambda X_h. Global bound X_h<=96 gives Lambda=96|lambda|; it is96, not192 (both source families are not simultaneously coupled). At lambda0 all source choices have identical dynamics and their exact old-kernel seed comparison must hold.

Review cache/resampling propagation and every changed branch/energy statement. Preserve L2 exhaustive checks, and on fixed visited L4 states compare every flippable move's cached complex O/X/count with literal flipped-state recomputation. Include a real-part-squared mutant that changes harmonic1 X, plus wrong source-slice and omitted cache copy controls. Pure conjugation of all O leaves X unchanged, so it is NOT a kernel-law discriminator by itself; signed complex source comparison can still detect the convention. Verify source shifts and physical energy per value. No enumerated L4 oracle or supplied ground vector.
