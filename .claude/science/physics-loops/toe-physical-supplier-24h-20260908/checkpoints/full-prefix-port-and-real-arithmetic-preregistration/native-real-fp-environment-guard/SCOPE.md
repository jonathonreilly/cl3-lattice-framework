# Same-process FP guard: exercised prerequisite, not universal conformance proof

The guard reads fegetround from the process C runtime and requires FE_TONEAREST=0 on the explicitly supported Darwin/Linux ABI. It never calls fesetround or changes FTZ/DAZ controls. Tiny real NumPy add/multiply arrays check normal addition and multiplication ties-to-even, least-normal/subnormal boundaries, signed zero, underflow ties and subnormal input preservation. Length variants exercise small loops and repeated blocks/tails. Expected outputs are literal binary64 bits independently verified by exact Fraction arithmetic and a nearest-even rounding oracle. Simulated Python-level FTZ/DAZ result/input corruptions are rejected; those controls do not change hardware FP state.

Run guard.check() in the actual certificate worker after NumPy loads, before certified arithmetic, and again before accepting its output. A check in a separate cost process does not establish the later worker's environment. Bind guard/interpreter/NumPy/ctypes source and extension identities in that worker's runtime closure. C runtime entry points, ABI constants and OS shared-cache libraries are an explicit platform boundary. The current receipt reports the actual platform and NumPy origin; it is not a complete runtime closure for a future certifier.

The checks exercise rounding and gradual-underflow paths and will catch FTZ/DAZ modes affecting those test operations. They cannot prove all compiler/ufunc paths, per-thread state, future environment stability, every alignment/length or IEEE conformance. The real-action8c2b and e7e08 certificate still require a declared real operation implementation, no reassociation, exact coefficient intervals, intermediate finiteness evidence and exact norm/residual accounting. Reading fegetround alone does not inspect every vector rounding control. These tiny operations are therefore a practical fail-closed prerequisite under the stated platform assumptions, not a replacement for them.

No overflow is deliberately induced. The actual action must preserve its per-product/per-add finite guards or independently prove bounds on finite intermediates. This guard itself requires all tested outputs finite. Underflow diagnostics are locally suppressed with numpy.errstate only to avoid warning noise; this does not alter rounding or FTZ/DAZ and restores NumPy's error handling on exit. No global hardware environment mutation, physical action,2^20 vector, CG or native arithmetic was run.

The first source/receipt before the added normal-product tie case are preserved. Final source was frozen again before its tiny execution. All exact-bit expectations and the two simulated adverse paths are retained separately.
